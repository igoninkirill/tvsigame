# Своя Игра — ТВ-студия

Веб-приложение для проведения «Своей Игры» в реальном помещении: телевизор работает игровым табло, ведущий управляет игрой со смартфона, игроки отвечают устно — приложение не требует их подключения.

## Состав

- **ТВ-экран** (`/room/:id/display`) — табло, вопросы, медиа, баллы, финал, итоги. Только отображение.
- **Пульт ведущего** (`/room/:id/host`) — мобильный интерфейс полного управления игрой.
- **Backend** (Go + PostgreSQL + WebSocket) — единственный источник истины: игровой движок-автомат, серверные таймеры, журнал событий, идемпотентные команды, отмена действий.
- **Импорт `.siq`** — пакеты SIBrowser/SIGame (формат v5, совместимость с v4; оба диалекта разметки: классический `scenario/atom` и новый `params/item`), включая медиа (картинки, аудио, видео — в вопросе и в раскрытии ответа) и спецвопросы (аукцион, кот в мешке, без риска, для всех).

## Быстрый старт (Docker)

Требуется только Docker с Compose:

```bash
docker compose up --build
```

Приложение поднимется на `http://localhost:8080`:

1. Откройте `http://<IP-сервера>:8080` на телевизоре → «Создать игру на ТВ».
2. На ТВ появится код комнаты.
3. На смартфоне откройте тот же адрес → «Я ведущий» → введите код.
4. Загрузите `.siq`-пакет (вкладка «Пакет»), добавьте игроков, начните игру.

Для игры по локальной сети телевизор и смартфон должны видеть сервер (одна Wi-Fi сеть).

## Локальная разработка

```bash
# 1. База данных
docker compose up -d db

# 2. Backend (порт 8080)
cp .env.example .env
cd backend
DATABASE_URL="postgres://sigame:sigame@localhost:5432/sigame?sslmode=disable" \
MEDIA_DIR=../data/media \
go run ./cmd/server

# 3. Frontend (порт 5173, проксирует /api, /ws, /media на :8080)
cd frontend
npm install
npm run dev
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_PORT` | `8080` | Порт HTTP-сервера |
| `DATABASE_URL` | — (обязательна) | Строка подключения к PostgreSQL |
| `MEDIA_DIR` | `./data/media` | Каталог медиафайлов пакетов |
| `STATIC_DIR` | — | Каталог собранного фронтенда (в Docker — `/srv/static`) |
| `MAX_UPLOAD_MB` | `512` | Лимит размера загружаемого `.siq` |
| `ROOM_TTL_HOURS` | `72` | Срок жизни комнаты |
| `HOST_GRACE_SEC` | `15` | Grace-период переподключения ведущего до автопаузы |

## Игровой процесс (сценарий MVP)

1. ТВ: создание комнаты → код на экране.
2. Ведущий: вход по коду → получение `host_token` (сессия переживает перезагрузку).
3. Ведущий: загрузка `.siq` или выбор пакета из библиотеки.
4. Ведущий: добавление игроков → «Начать игру».
5. Заставка раунда: ТВ объявляет темы по одной → ведущий жмёт «К табло» (можно и сразу, пропустив заставку).
6. Выбор вопроса на табло → показ на ТВ (текст, картинки, аудио, видео из пакета) → «Разрешить отвечать» → выбор отвечающего (на ТВ он подсвечивается со значком «отвечает») → вердикт «Верно/Неверно» → баллы начисляются сервером. При раскрытии ответа показываются и медиа ответа из пакета.
7. Спецвопросы: аукцион (торги, ва-банк, пас), кот в мешке (передача), без риска, для всех (вердикт по каждому).
8. Финал: исключение тем → скрытые ставки → финальный вопрос → вердикты → итоговая таблица и победитель.
9. В любой момент: пауза/продолжение, отмена последнего действия, ручная корректировка счёта, история событий.

Отключение ведущего автоматически ставит игру на паузу (после grace-периода); при возвращении игра продолжается с того же места. Перезапуск backend не теряет состояние.

### Озвучка ТВ

ТВ озвучивает ключевые моменты аутентичными сэмплами телеигры (из открытого проекта SIGame, MIT): джингл и музыка заставки раунда, кот в мешке, аукцион, «для всех», «без риска», «время вышло», верный ответ (аплодисменты), неверный (фирменный «бззз»), исключение тем финала, 60 секунд финальных размышлений, финальные аплодисменты. Кнопка вкл/выкл — в углу ТВ-экрана; браузеры разблокируют звук после первого касания экрана.

## Проверка MVP

Сквозной сценарий из ТЗ §16 покрыт смоук-тестом (нужен запущенный backend):

```bash
python3 scripts/smoke.py            # против http://localhost:8080
```

Тест проходит: создание комнаты → вход ведущего → импорт `.siq` → игроки → старт → обычные вопросы (верно/неверно/повторная попытка) → аукцион (валидация ставок, авто-завершение торгов) → кот в мешке → финал (исключение тем, скрытые ставки, вердикты) → итоги → отмена действия → идемпотентность → конфликт версий.


## Безопасность

- Токены хранятся в БД только в виде SHA-256 хэша; в URL не передаются (WS-аутентификация — первым сообщением соединения).
- Код комнаты: алфавит без визуально неоднозначных символов, rate-limit на подбор.
- Импорт `.siq`: защита от ZIP Slip, лимиты размера, извлекаются только используемые медиа; `encoding/xml` не обрабатывает внешние сущности (XXE исключён по построению).
- Игровые команды идемпотентны (`action_id`), с оптимистичной проверкой `expected_state_version`.

## Ограничения MVP (по ТЗ)

Не реализовано намеренно: подключение игроков со смартфонов, кнопка «я первый», режим зрителя, аккаунты, рейтинги, чат. Архитектура (роли подключений, команды движка, журнал событий) позволяет добавить это позже.
